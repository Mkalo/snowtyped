# Live Snowflake coverage

Maps each supported runtime feature to the live tests that assert its SQL behavior
and returned values against Snowflake. Files are under `tests/integration/`. Every
file creates its own `SFLIB_TEST_<uuid>` schema through `tests/support/snowflake.ts`
and drops it afterwards.

Every public runtime export and builder method must appear in backticks in the
first column of a table below; `tests/unit/live-coverage.test.ts` enforces that,
including column methods and the `structuredType` and `rowPattern` namespaces. A
feature with server semantics needs a live row. Type-only contracts, invalid
construction, client-side guards, and packaging stay in type, unit, and package
tests and are listed under exclusions with the reason.

## Exclusions

| Feature                                                                                                                     | Covered by                                                | Reason                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `compileAst`, `.compile`, `identifier`, `quoteIdentifier`, `compileDdl`                                                     | unit tests                                                | Exercised by every live statement; direct calls have no separate server semantics                 |
| `.encode`, `.encodeWrite`                                                                                                   | unit tests                                                | Column codecs used by every live write and filter; direct calls have no separate server semantics |
| Builder and semantic validation (scope, phase, QUALIFY, ASOF operator, identifier limits, empty mutations, SQL type checks) | unit and type tests                                       | Rejected before SQL reaches Snowflake; `semantics` checks that valid cases still run              |
| Transaction guards (reserved connection, expired client, nested transactions, running queries)                              | `tests/unit/execution.test.ts`                            | Client-side state; races cannot be reproduced reliably against a server                           |
| Cancellation races (abort before/after completion, cancel failures)                                                         | `tests/unit/execution.test.ts`, `tests/unit/pool.test.ts` | Timing-dependent; live tests cover the deterministic paths                                        |
| Unsupported types in generated declarations                                                                                 | `tests/unit/introspection.test.ts`                        | Every column type Snowflake reports for a table is supported, so no live table can produce one    |
| Packaging, exports, tree shaking                                                                                            | package tests                                             | No server semantics                                                                               |

## Known gaps

None open. A bug found by a live probe is filed as an issue and listed here with
its fix PR until the fix lands with its live test; the suite never asserts the
wrong behavior.
