The canonical rules live in
[CONTRIBUTING.md](https://github.com/Mkalo/snowtyped/blob/main/CONTRIBUTING.md). This page
summarizes them.

## Local checks

Use the pnpm version pinned in `package.json` and Node.js 22.18+ or 24.11+.

```sh
pnpm install --frozen-lockfile
pnpm check
```

`pnpm check` runs Biome, strict TypeScript checks and type fixtures, offline unit tests with 100%
per-file coverage thresholds, ESM/CJS builds, publint, Are the Types Wrong, and tests against an
installed tarball. None of these need Snowflake credentials.

## Architecture boundaries

- `ast.ts` models Snowflake syntax independently of the SDK and runtime schemas.
- `schema.ts` owns column domains, wire decoding, and schema-derived validation.
- `query.ts` owns immutable query construction and scope rules.
- `snowflake/` adapts an existing `snowflake-sdk` connection.

A new operation defines its AST representation, input types, scope, inferred output, SQL compilation,
and runtime validation together. Prefer semantic nodes over raw SQL fragments, and never require
callers to provide decoders.

## Tests

Add behavioral unit tests and compile-time fixtures for new public typing contracts. Unit tests must
never require Snowflake credentials, and coverage thresholds are 100% per source file.

### Integration tests

New Snowflake semantics need opt-in integration coverage. The suite uses a dedicated service user,
role, database, and X-Small warehouse, authenticated with an RSA key pair.

```sh
pnpm snowflake:setup     # creates a key pair, bootstrap SQL, and .env.integration
pnpm test:integration
```

Run the generated bootstrap SQL as `ACCOUNTADMIN`, then fill in the account identifier in
`.env.integration`. Each run creates a `SFLIB_TEST_<uuid>` schema, seeds fixtures, and drops only
that schema. Full instructions are in
[Snowflake setup](https://github.com/Mkalo/snowtyped/blob/main/docs/snowflake-setup.md).

## Documentation

This site is the authoritative user documentation. Changes to public APIs, behavior, or feature
boundaries update the matching guide pages in `website/src/content/docs/`. The site lives in
`website/` as a separate pnpm project, so its dependencies never reach the published package. Code examples are TypeScript files in `website/src/snippets/` that are type
checked against the library source.

```sh
pnpm install --frozen-lockfile        # library dependencies, used by the snippets
cd website
pnpm install --frozen-lockfile
pnpm dev                              # local preview
pnpm check                            # type checks, strict build with link validation, tests
```

The tests fail when a runtime export of `snowtyped` or `snowtyped/snowflake` is not named in any
guide or snippet. Removed limitations cannot be detected automatically, so update
[feature status](/guides/feature-status/) by hand when a feature lands.

The site needs Node.js 22.23.4 or later because of its Astro toolchain.
