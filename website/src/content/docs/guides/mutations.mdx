- `insert(table, values)` accepts one row or an array of rows. Required columns must be present.
  Omitted columns are left out of the statement, so Snowflake applies their DEFAULT, identity, or
  NULL. An explicit `null` writes SQL NULL, including on VARIANT columns, where it is not JSON
  `null`.
- `update(table, values)` accepts typed literal values and expressions from its own table.
- Statements resolve to `{ affectedRows, queryId }`. There is no emulated RETURNING clause.

<Aside type="caution">
  UPDATE and DELETE without `.where()` affect every row in the table.
</Aside>

## Defaults, identity, and virtual columns

Declare server-populated columns with `.serverDefault(sql?)` or `.identity({ start, increment, order }?)`
so they are optional on insert even when `.notNull()`. `.virtual(sql?)` marks a computed `AS (expr)`
column. It is read-only: insert, update, and MERGE types exclude it and reject it at runtime. These
modifiers are metadata only and do not emit DDL.

<Snippet code={serverValues} />

Rows that omit different columns compile to one conditional `INSERT ALL` that uses DEFAULT per row.
Snowflake consumes identity and sequence values for every branch, so such inserts leave gaps.
