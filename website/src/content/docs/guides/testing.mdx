## Compiled SQL

touching Snowflake, and so do raw `sql` fragments. Use it for fast, credential-free unit tests.

## Live Snowflake tests

Behavior that depends on Snowflake itself, such as decoding, privileges, or time travel retention,
needs a real account. Give tests a dedicated role and database, have each run create its own
uniquely named schema, and drop only the schemas that run created. Live tests consume Snowflake
credits.

Snowtyped's own integration suite follows this pattern. See the
[Snowflake setup guide](/project/contributing/#integration-tests) for the account, role, and key-pair
configuration it uses.
